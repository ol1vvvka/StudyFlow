# StudyFlow — концепция продукта

> Рабочий документ. Обновляется по мере принятия решений.

## Проблема

Учебные материалы студента разбросаны по разным местам:
PDF лекций лежат в чатах Telegram, фото конспектов — в галерее вперемешку с личными фото,
Word-файлы — в почте, расписание — в отдельном приложении, карточки — в Anki/Quizlet,
а дедлайны люди держат в голове. Перед сессией начинается поиск и паника.

## Решение

Одно приложение, где всё собрано вокруг **предмета** (дисциплины): материалы, заметки,
карточки, дедлайны и экзамены. Поверх этого — «умный» слой: из фото конспекта или PDF
лекции приложение само делает текст, краткую выжимку и карточки для повторения.

## Целевая аудитория

1. Студенты вузов и колледжей — основная аудитория.
2. Школьники 9–11 классов, которые готовятся к ОГЭ/ЕГЭ.
3. Те, кто учится сам или проходит онлайн-курсы.

## Конкуренты и чем мы отличаемся

| Продукт | Сильная сторона | Чего не хватает |
|---|---|---|
| Notion, OneNote | Гибкость | Всё приходится строить самому; нет интервальных повторений |
| Anki, Quizlet | Карточки и повторения | Только карточки; создавать их вручную долго |
| GoodNotes, Notability | Рукописные заметки | Заточены под iPad; нет календаря и карточек |
| Google Classroom, Moodle | Курсы от преподавателя | Не личное пространство студента |

**Наше отличие:** предмет как центральная сущность, автоматизация («фото → текст → карточки»)
и режим подготовки к экзамену, который собирает всё по предмету в один план.

## Модель данных (верхний уровень)

```
Семестр
 └─ Предмет (цвет, иконка, преподаватель)
     ├─ Материалы: PDF, DOCX, фото, видео, ссылки
     ├─ Заметки
     ├─ Колоды карточек → Карточки (с состоянием интервальных повторений)
     └─ События: пары, дедлайны, контрольные, экзамены
Теги — общие для всех сущностей
```

## Этапы

### MVP (v0.1) — работает локально, без аккаунтов

**Статус на 28.10.2026:** готовы предметы, материалы, заметки с автосохранением и поиском.
Подготовлены Яндекс ID и резервное копирование материалов и заметок.
Дальше — календарь, оформление интерфейса, карточки и «Сегодня».

1. **Предметы:** создание, редактирование и удаление; цвет, иконка, семестр.
2. **Материалы:** импорт файлов (PDF, DOCX, изображения, видео), снимок конспекта камерой,
   открытие во внешнем приложении, превью изображений, поиск по названию.
3. **Заметки:** текстовые заметки с привязкой к предмету.
4. **Карточки:** колоды, режим повторения, интервальные повторения по алгоритму SM-2.
5. **Календарь:** дедлайны, экзамены и пары; список на неделю.
6. **Главная «Сегодня»:** карточки на повторение, ближайшие дедлайны, недавние материалы.

### v0.2 — облако
Аккаунты, синхронизация между устройствами, резервные копии.

### v0.3 — «умный» слой
OCR фото конспектов, генерация карточек и выжимок из PDF и конспектов через LLM,
поиск по содержимому файлов.

### v0.4 — совместная работа
Общий предмет для учебной группы, обмен колодами, импорт расписания вуза.

## Монетизация (гипотеза)

Модель freemium:
- **Бесплатно:** локальное хранение, ограниченный объём облака, ручные карточки.
- **Pro (подписка):** больше места в облаке, AI-генерация карточек и выжимок, OCR,
  синхронизация на всех устройствах.

## Технологии

- **Клиент:** .NET MAUI (.NET 10). Сначала Android и Windows; iOS и macOS позже
  (для их сборки нужен Mac).
- **MVVM и UI:** CommunityToolkit.Mvvm, CommunityToolkit.Maui, Syncfusion.Maui.Toolkit.
- **Локальные данные:** SQLite (Microsoft.Data.Sqlite). Файлы лежат в `AppDataDirectory`,
  в базе хранятся только их метаданные.
- **Язык интерфейса:** русский; строки вынесены в `.resx`, чтобы позже добавить английский.
- **Сервер (с v0.2):** ASP.NET Core Web API, PostgreSQL, S3-совместимое хранилище файлов.
- **AI (с v0.3):** LLM вызывается только с сервера, ключ API в клиент не попадает.

## Как проверяем гипотезу

- 10–15 интервью со студентами до и во время разработки MVP: как они сейчас хранят
  материалы и готовятся к экзаменам.
- Метрики после запуска: удержание на 7-й день (D7), число предметов на пользователя,
  число повторений карточек в неделю.
