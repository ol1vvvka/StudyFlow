# Правила StudyFlow

## Ветки

Эти правила относятся только к StudyFlow и имеют приоритет над общими соглашениями об именовании веток.

- `main` — только релизы. Повседневную разработку и отдельные исправления напрямую сюда не коммитить и не вливать.
- `dev` — интеграционная ветка разработки.
- `fix` — интеграционная ветка исправлений.
- В проекте использовать только три ветки: `main`, `dev`, `fix`. Ветки с `/` и отдельные тематические ветки не создавать.
- В `main` вливать подготовленный релиз из соответствующей интеграционной ветки только по явному указанию пользователя выпустить релиз.
- Подготовленные исправления переносить между `fix` и `dev` по необходимости, сохраняя обе линии актуальными. Не изменять уже опубликованную историю без отдельного согласования.
- Общие схемы `dev1c/...`, `feature/...` и `bugfix/...` в этом проекте не применять.

## Коммиты и документация

- Автор и коммитер — подтверждённая учётная запись пользователя.
- Сообщения коммитов — на русском, с конкретным описанием изменения. Не добавлять стороннее соавторство, водяные знаки или подписи о происхождении кода.
- Перед пушем обновлять README при изменении возможностей или запуска; CHANGELOG — соразмерно значимым изменениям. Не объявлять релиз до его фактического выпуска.
- Локальные конфиги, настройки среды, токены, ключи, базы и сборки не публиковать. Примеры конфигурации должны оставаться безопасными и позволять собрать чистую копию.
- Открытая часть проекта — Apache License 2.0. Будущие закрытые расширения хранить отдельно до первой публикации их кода.
